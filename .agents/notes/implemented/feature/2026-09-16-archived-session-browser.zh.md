# Agent Note: 已归档会话浏览与恢复

Status: implemented

[English](2026-09-16-archived-session-browser.md) | 中文

## Problem

归档会隐藏会话，但不会删除历史。用户需要检查保留的历史并恢复会话，而不必编辑 Harness 存储文件。

## Decision

Workspace UI 通过现有 Slots 导航贡献“已归档”主面板及对应侧栏入口。面板根据 Workspace Controller 的归档集合和 Session Controller 的摘要派生列表，不复制会话业务数据。打开列表项会选择现有 Conversation，不改变归档状态。取消归档只移除持久化归档标记，保留工作区会话归属与历史。

导航只在当前会话进入归档集合时清空选择，包括初始选择已归档会话的情况。主动打开已归档会话是允许的。观察器先记录新的归档集合，再清空选择，避免同步选择通知重复处理同一次变化。

注册表将取消归档与其他工作区写操作串行执行；不存在归档标记时不执行写入。取消归档不要求会话日志存在：外部存储删除导致内容不可用时，用户仍可清除残留归档标记。

## Alternatives considered

**查看时自动取消归档。** 阅读历史不应改变会话是否出现在普通列表中；恢复仍是显式操作。

**独立的历史渲染器。** 复用 Conversation 可保留分页以及现有消息和工具展示，避免第二套历史实现。归档是可见性偏好，不是只读限制或权限限制。

**清空所有已归档选择。** 只判断集合成员关系的导航守卫会阻止用户打开归档内容。基于状态变化的清空策略既保留归档操作的行为，也允许主动查看。

## Consequences

归档集合仍是唯一持久化权威。恢复的会话按照既有归属及排序策略重新进入普通列表；无需重写日志或迁移数据。摘要缺失时，列表可保留归档项，禁用内容查看并允许取消归档。打开归档内容使用普通 Conversation 功能，而不是只读模式。

现有[客户端所有权决策](../architecture/2026-08-20-client-session-conversation-ownership.zh.md)仍然有效：页面消费 Controller 快照，而不在 UI store 中保存业务数据。本决策未取代任何有效的归档专项决策。
